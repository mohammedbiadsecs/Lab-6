# Binary Search — 61-second explainer

**Learning objective:** After one minute, the viewer understands that binary search requires a sorted array, checks the middle of the current range, discards half after each unsuccessful comparison, and needs far fewer comparisons than linear search.

**Stack:** Codex, Remotion, Kokoro, FFmpeg. English voice: Kokoro `af_sarah` at 1.12× speed. Composition: `BinarySearch`, 1280×720, 30 FPS.

| Time | Visual | Narration |
|---|---|---|
| 0–9 s | Title and sorted-array rule | Binary search finds a value by repeatedly cutting a sorted search range in half. The array must be sorted first. |
| 9–18 s | Show `[2, 5, 8, 12, 16, 23, 38, 56, 72]`; target 56 | Let's find fifty six in this sorted array. We start with all nine numbers and inspect the middle. |
| 18–26 s | Highlight 16, then dim 2 through 16 | The middle is sixteen. Fifty six is larger, so everything through sixteen can be discarded. |
| 26–34 s | Highlight 38, then dim 23 and 38 | The new middle is thirty eight. Fifty six is still larger. Discard the left part again. |
| 34–42 s | Highlight 56 in green | Now the middle is fifty six. That's our target. Found in just three comparisons. |
| 42–54 s | `O(n)` versus `O(log n)`; 1,000,000 versus 20 | Linear search checks items one by one: order n. Binary search halves the range: order log n. In one million sorted elements, that's up to one million comparisons versus only twenty. |
| 54–61 s | Three-step takeaway | Remember: sort first, check the middle, and keep only the possible half. That's binary search. |
